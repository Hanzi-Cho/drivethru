# DriveThru UI Requirements

## 1. 글로벌 구조

앱은 하단 탭 4개를 기준으로 구성된다.

- `Menu`
- `Cart`
- `Order`
- `Setting`

모든 페이지는 아래 글로벌 상단 영역을 공유한다.

왼쪽:
- `Prev` 버튼
- `Drive-Thru` 앱 이름

오른쪽:
- 주행 중 조작 주의 강조 탭
- 데이터 연결 수준
- Wi-Fi 수준
- 배터리 수준
- 현재 시각

디자인 기준:
- 첨부 시안 비주얼을 우선 레퍼런스로 사용한다.
- 상단바와 하단바는 페이지가 바뀌어도 동일 높이와 동일 패딩을 유지한다.
- 라운드 값은 `tokens.json`의 radius를 기준으로 통일한다.

## 2. 글로벌 동작 원칙

- `DRIVE` 또는 제한 상태에서는 빨간 경고 탭이 노출될 수 있다.
- `PARK` 상태에서는 경고 탭이 축소되거나 `Park Mode` / `Safe Order Mode` 배지로 바뀔 수 있다.
- 상단바 정보는 모든 페이지에서 고정 유지된다.
- 하단 탭은 모든 페이지에서 고정 유지된다.
- 현재 페이지 탭은 채움형 active 스타일을 사용한다.

## 3. 하단바 요구사항

하단바는 4개의 탭으로 구성된다.

- `Menu`
- `Cart`
- `Order`
- `Setting`

규칙:
- 아이콘 + 라벨 조합
- active 탭은 채워진 pill 또는 rounded rect
- inactive 탭은 아이콘/텍스트만 유지
- `Cart`는 수량 badge 허용
- 탭 높이는 터치 타깃 기준으로 충분히 크게 유지
- active 배경은 yellow 계열, inactive는 dark bar 위 저채도 text 계열
- 아이콘과 라벨은 수직 중앙 정렬
- 탭 순서는 고정이며 페이지별 재배치 금지

## 4. Menu 페이지

구조:
- 좌측 카테고리 탭 컬럼
- 우측 전체 메뉴 스크롤 영역
- 좌하단 `ORDER SUMMARY`

세부 요구사항:
- 왼쪽 카테고리 탭은 세로 리스트
- 오른쪽은 모든 카테고리가 이어지는 단일 scroll view
- 아래로 스크롤하면 다음 카테고리 섹션으로 자연스럽게 이동
- 왼쪽 카테고리 탭을 누르면 오른쪽 해당 카테고리 영역으로 점프
- 현재 보이는 카테고리에 맞춰 왼쪽 active 상태 동기화 필요
- 각 카테고리 섹션 타이틀 뒤에는 길게 이어지는 얇은 구분선을 둔다
- 카테고리 rail과 메뉴 리스트 사이에는 세로 divider가 존재한다

메뉴 카드 정보:
- 이미지
- 이름
- 짧은 설명
- 가격
- `ADD` 버튼

메뉴 카드 구조:
- 썸네일은 좌측 고정
- 텍스트는 중앙 확장
- 가격은 우측 상단 정렬
- CTA는 우측 고정 폭 버튼
- 설명은 2줄 제한

좌하단 `ORDER SUMMARY`:
- 좌하단 총 금액
- 우하단 선택 개수
- 항상 현재 장바구니 상태와 동기화
- 비어 있어도 패널을 숨기지 않는다
- 금액과 개수의 시각적 위계는 금액이 더 커야 한다

운전 중 제한 원칙:
- `DRIVE` 상태에서는 카드 수를 줄이거나 quick order 버전으로 다운그레이드 가능
- 긴 설명은 1줄 또는 2줄 이내

## 5. Cart 페이지

상단 안내 바:
- 좌측 `주문 내역 확인`
- 우측 `Order Review`
- 전체 폭 안내 바는 카드가 아니라 강조 band로 취급한다

좌측 영역:
- 선택한 메뉴 리스트
- 각 메뉴에 `-`, `+`, `삭제` 버튼 존재
- 이미지, 이름, 하위 선택 옵션, 가격, 선택 개수 표시
- 리스트 셀은 동일 높이로 정렬한다
- 옵션은 칩 또는 단문 텍스트로 표시한다
- 수량 조절은 별도 사각 stepper 안에 넣는다

우측 영역:
- 결제 정보 패널
- 주문 금액
- 할인 금액
- 총 결제 금액 강조
- 결제 버튼
- 저장 카드 이미지
- 일부 마스킹된 카드번호 표기
- 자동결제 성격을 암시하는 문구 또는 아이콘
- 총 결제 금액이 시각적 최우선이어야 한다
- primary CTA와 secondary CTA는 동일 폭, 동일 높이 유지

보조 정보:
- 픽업/처리 안내 정보 카드 허용

## 6. Order 페이지

전제:
- 주문 완료 후 이 페이지로 이동

포함 정보:
- 주문한 메뉴 요약
- 전방 픽업 존으로 이동 안내 텍스트
- 결제 수단 이름
- 카드사/카드명
- 일부 마스킹 카드번호
- 결제 금액
- `Order summary`
- 완료 아이콘은 중앙 정렬
- 상태 메시지와 summary는 분리된 카드 그룹으로 둔다

상태:
- `Processing`
- `Payment Complete`
- `Ready for Pickup`

현재 시안 기준으로 `Payment Complete + Order Summary` 조합을 기본안으로 유지한다.

## 7. Setting 페이지

아이템:
- 결제 수단 설정
- 이전 거래 내역
- 즐겨찾기 주소 설정
- 계정 관리

선택 확장:
- 언어
- 접근성
- 개인정보/자동결제 동의

레이아웃:
- 2x2 카드 그리드 우선
- 하단에 보안/브랜드 메시지 배너 허용
- 각 카드에는 leading icon, title, subtitle, trailing chevron을 둔다
- 배너는 이미지 위 오버레이 텍스트를 허용한다

## 8. 상태 의미

상태 배지는 아래 의미를 갖는다.

- `red`
  - 주행 중 조작 주의
  - high attention required
- `yellow/amber`
  - 브랜드 주요 액션
  - 결제 CTA
  - 선택 상태
- `teal`
  - 정보/연결/서비스 보조 상태
- `green`
  - 완료
  - 성공
  - 안전 모드

## 9. 페이지별 우선순위

정보 우선순위는 다음과 같다.

### Menu
- 카테고리
- 메뉴 이름
- 가격
- 추가 버튼
- 장바구니 요약

### Cart
- 선택한 메뉴
- 총 결제 금액
- 결제 버튼
- 카드 정보

### Order
- 주문 완료 상태
- 픽업 안내
- 결제 정보
- 주문 요약

### Setting
- 자주 쓰는 설정
- 결제 관련 진입점
- 계정/이력 관리

## 10. 반응형/해상도 원칙

Landscape 기준:
- 좌우 2열 활용 가능
- `Menu`는 좌측 category rail + 우측 content
- `Cart`는 좌측 item list + 우측 payment panel

Portrait 기준:
- 카테고리는 horizontal chips 또는 compact left rail 변형 검토
- `Cart`는 payment panel이 하단으로 내려갈 수 있음
- 상단 상태 정보는 더 압축

## 11. 구현 우선순위

1. Landscape design system 확정
2. 하단바와 상단바 공통 컴포넌트 확정
3. `Menu`, `Cart`, `Order`, `Setting` 상세 요구사항 고정
4. 토큰 기반 색상/간격 적용
5. 이후 simulator와 app mock에 반영

## 12. 세부 타이포 우선 규칙

- 페이지 타이틀: `32~40px`, `700`
- 섹션 타이틀: `28px`, `700`
- 카드 타이틀: `18~24px`, `700`
- 본문 설명: `14~16px`, `400~500`
- 가격: `22~40px`, `700`
- 버튼 라벨: `16~18px`, `700`
- 보조 라벨: `11~14px`, `600`
